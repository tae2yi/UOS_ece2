이 문서는 **이번에 제공한 4주 실습 매뉴얼의 한 부분**이다. 같은 매뉴얼로 4주 전체를 진행한다.

먼저 [예제 시작과 전환](index.md#예제-시작과-전환)을 확인해 이전 실습 코드를 정리한다.

## 코드 읽기
- `UART_HandleTypeDef`는 UART 설정과 상태를 묶은 **구조체 자료형**이고, huart3는 그 자료형의 변수다.
- `HAL_StatusTypeDef`는 처리 결과를 나타내는 **enum 자료형**이다. 정상은 HAL_OK(0), 오류는 HAL_ERROR(1), 사용 중은 HAL_BUSY(2), 시간 초과는 HAL_TIMEOUT(3)이다.
- `getchar()`는 문자 하나를 읽는다. EOF도 표현해야 하므로 결과를 int에 저장한다.
- `uint8_t`는 한 바이트 값을 저장한다. `(uint8_t)ch`는 ch를 그 자료형으로 변환한다.
- `HAL_UART_Transmit(&huart3, &data, 1U, 100U)`는 UART3로 data의 한 바이트를 보낸다. 마지막 100은 기다리는 최대 시간 100 ms다.
- `&huart3`, `&data`는 각각 장치 변수와 보낼 데이터의 주소다.

## 컴퓨터 입출력
[Serial Monitor 설정](../README.md#컴퓨터에서-출력-확인하기)을 따라 **9600, 8비트, 패리티 없음, 정지 비트 1**로 연결한다. UART2는 보드 내부에서 ST-LINK USB로 연결된다.

> [!TIP]
> **제공 코드 · ece2_474_routine.c의 polling_routine 교체**
>
> ```c
> void polling_routine(void)
> {
>     int ch = getchar();
>     if (ch != EOF)
>     {
>         printf("받은 문자: %c\r\n", ch);
>     }
> }
> ```

입력이 올 때까지 이 함수에서 기다린다. Serial Monitor의 보내기 기능으로 문자를 전송한다. 한 줄 입력은 `fgets`로 받을 수 있으며, 줄바꿈 문자까지 보내야 한다.

## STM32에서 FPGA로 보내기

**MCU–FPGA 연결은 자기 조의 MCU와 FPGA로 진행한다. 옆 조와 함께하거나 다른 조 장비를 빌릴 필요가 없다.**

STM32 PC10(TX)을 FPGA 확장 GPIO의 RX에 연결하고 GND를 서로 연결한다. 양쪽 모두 9600으로 맞춘다. 이번 제공 코드는 MCU에서 FPGA로 보내는 한 방향 전송이다. MCU가 FPGA의 응답까지 받도록 추가 구현할 때만 별도 FPGA TX를 PC11(RX)에 연결한다.

### MCU와 FPGA의 핀 설정 구분

| 대상 | 핀 설정 방법 | 이번 실습에서 할 일 |
|---|---|---|
| **MCU · STM32** | **IOC 설정에서 생성된 C 코드** | 제공된 PC10(TX)·PC11(RX) 설정을 사용한다. |
| **FPGA** | **FPGA 프로젝트의 XDC 파일** | 점퍼선을 연결할 FPGA 확장 GPIO 핀을 RX로 지정한다. |

**MCU에는 XDC 파일이 없다. 아래의 XDC 수정은 모두 FPGA 프로젝트에서 하는 작업이다.** MCU 핀 번호를 XDC에 적는 것이 아니라, FPGA 신호 이름과 FPGA 칩의 핀 번호를 연결한다.
### FPGA UART 입력 핀 변경

기존 LAB3 UART 에코 예제의 RX는 보드 내부 USB-UART에 연결된 **C6**, TX는 **F6**다. RX가 C6로 지정된 상태에서는 MCU의 점퍼선 입력을 받는 회로가 아니다.

- MCU의 **PC10(TX)**을 연결할 FPGA 확장 GPIO 핀을 장비 핀맵에서 고르고, 실제 커넥터 위치를 확인한다.
- FPGA UART 수신 모듈의 RX 입력을 그 핀에 연결하고, **FPGA 프로젝트 XDC**의 RX `PACKAGE_PIN`을 해당 FPGA 칩의 핀 번호로 바꾼다. 신호 기준은 `LVCMOS33`으로 맞춘다.
- 수신 결과를 PC에 출력할 FPGA UART TX는 기존 **F6 → 보드 USB-UART** 연결을 유지할 수 있다. RX 핀 변경 후 다시 bit 파일을 만들고 FPGA에 다운로드한다.
- MCU로 응답까지 보내려면 확장 GPIO에 별도 FPGA TX 출력을 두고 MCU **PC11(RX)**에 연결한다. PC 출력과 같은 송신 데이터를 두 출력으로 내보내거나 별도 송신 회로를 사용한다.
- 한 방향 전송만 확인할 때는 **MCU PC10 → FPGA RX와 GND**만 연결해도 된다.

| 목적 | 연결 |
|---|---|
| MCU가 FPGA로 보내기 | MCU PC10 → FPGA 프로젝트 XDC에서 지정한 확장 GPIO RX |
| FPGA가 PC에 수신 결과 출력 | FPGA F6 → 보드 내부 USB-UART → PC |
| FPGA가 MCU로 응답 · 추가 구현 시 | 별도 FPGA 확장 GPIO TX → MCU PC11 |
| 공통 접지 | MCU GND ↔ FPGA GND |

기존 USB-UART의 RX와 새 점퍼선 입력 RX를 같은 입력 핀으로 착각하지 않는다. 기존 PC 입력도 함께 받고 싶다면 수신 회로를 별도로 두어야 한다.

> [!TIP]
> 주변장치 변수 huart3은 ece2_474.h에 이미 선언되어 있다. 추가 선언 없이 사용한다.
>
> **polling_routine 교체 · PC에서 받은 한 바이트를 FPGA로 전송**
>
> ```c
> void polling_routine(void)
> {
>     int ch = getchar();
>     if (ch != EOF)
>     {
>         uint8_t data = (uint8_t)ch;
>         HAL_StatusTypeDef result =
>             HAL_UART_Transmit(&huart3, &data, 1U, 100U);
>         printf("전송 결과: %d\r\n", (int)result);
>     }
> }
> ```

전송 결과 0은 STM32의 송신 함수가 정상 종료했다는 뜻이다. FPGA가 받은 값은 FPGA 출력으로 따로 확인한다.

## 직접 작성할 과제 · 총 3개

PC 입력부터 FPGA 제어까지 아래 순서대로 확인한다. 이전 단계가 동작한 뒤 다음 단계로 진행한다. 추가 정답 코드는 제공하지 않는다.

| 과제 | 데이터 흐름 | 확인할 결과 |
|---|---|---|
| STM32_2_과제5 | PC → MCU → PC | 입력한 문자와 바이트 값 출력 |
| STM32_2_과제6 | PC → MCU → FPGA → PC | FPGA가 받은 문자가 원래 입력과 일치 |
| STM32_2_과제7 | PC → MCU → FPGA | 명령에 따라 FPGA LED 상태 변경 |

### STM32_2_과제5 · PC와 MCU 입출력 확인

컴퓨터 입출력 예제를 수정해 PC에서 보낸 문자 한 개를 MCU가 받고, 받은 **문자와 그 바이트 값을 16진수로** VCP UART에 출력한다.

- PC Serial Monitor는 **9600, 8비트, 패리티 없음, 정지 비트 1**로 설정한다.
- 한 문자 확인에서는 보내기 설정의 줄바꿈을 **없음(None)**으로 선택한다.
- 문자 `1`, `A`, `a`를 각각 보내고 표시되는 값이 **0x31, 0x41, 0x61**인지 확인한다.
- 입력이 없을 때 getchar가 기다리는 상태와 프로그램이 오류로 멈춘 상태를 구분한다.

이 단계에서는 FPGA와 점퍼선을 연결하지 않아도 된다.

### STM32_2_과제6 · MCU에서 FPGA로 보낸 값 확인

**PC → VCP → MCU → 점퍼선 → FPGA → USB-UART → PC**


위의 MCU 송신 예제를 사용해 **PC에서 받은 한 바이트를 UART3로 FPGA에 전달**한다. FPGA는 받은 문자를 자체 UART로 PC에 출력한다.

- MCU **PC10(TX) → FPGA 확장 GPIO RX**, 양쪽 **GND**를 연결한다.
- **FPGA 프로젝트의 XDC만** 앞의 **FPGA UART 입력 핀 변경** 안내에 따라 수정한다. MCU의 PC10 핀 설정은 제공 코드 그대로 사용한다. MCU와 FPGA 모두 **9600, 8N1**로 맞춘다.
- PC에는 MCU VCP와 FPGA USB-UART의 **서로 다른 COM 포트**가 나타난다. MCU 포트로 문자를 보내고, FPGA 포트에서 수신 결과를 확인한다. 두 포트를 각각 열어 동시에 확인한다.
- 과제5에서 확인한 문자를 보내 FPGA 출력과 비교한다. MCU 송신 결과가 0이라는 것만으로 수신 성공으로 판단하지 않는다.

FPGA UART 출력 기능은 기존 실습의 송신 회로를 사용한다. 이 단계는 MCU가 FPGA의 응답을 받는 동작이 아니라 **FPGA가 PC에 수신 결과를 출력하는 동작**이다.

### STM32_2_과제7 · UART 명령으로 FPGA LED 제어

과제6의 FPGA 수신 처리를 확장해, 받은 문자에 따라 LED 상태를 변경한다.

| PC에서 보낼 문자 | FPGA 동작 |
|---|---|
| `0` | 지정한 LED 끄기 |
| `1` | 지정한 LED 켜기 |
| `2` | 지정한 LED 상태 반전 |
| 그 밖의 문자 | LED 상태 유지 |

각 명령을 여러 번 보내고 실제 LED 상태를 확인한다. 특히 `1`을 반복하면 계속 켜져 있고, `2`를 반복하면 매번 상태가 반전되어야 한다. FPGA UART 출력으로 받은 명령도 함께 확인한다.

> [!NOTE]
> 문자 '1'의 바이트 값은 0x31이다. 숫자 1인 0x01과 구분한다. 현재 getchar와 UART2 인터럽트 수신은 함께 사용하지 않는다.

> [!NOTE]
> **10/26 STM32_2에서 10분 퀴즈를 실시할 수 있음.** 실시 여부와 범위는 별도로 안내한다.

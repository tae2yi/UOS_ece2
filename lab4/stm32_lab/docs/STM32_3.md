# STM32_3 · SPI로 MCU와 FPGA 연결
**11/2** · [목차](index.md)

이 문서는 **이번에 제공한 4주 실습 매뉴얼의 한 부분**이다. 같은 매뉴얼로 4주 전체를 진행한다.

먼저 [예제 시작과 전환](index.md#예제-시작과-전환)을 확인해 이전 실습 코드를 정리한다.

## 이번 주차의 목표

MCU에서 SPI 송신·수신을 실행하고, FPGA에서는 SPI 회로를 직접 작성한다. **I²C는 이번 실습에서 수행하지 않는다.** Verilog 정답 코드는 제공하지 않는다.

## SPI의 동작

마스터가 SCK를 만들고, 슬레이브는 전달받은 SCK에 맞춰 데이터를 받는다. CS가 LOW인 동안 선택된 장치와 통신한다. 이번 실습은 **Mode 0, 8비트, 높은 비트부터 전송**으로 통일한다.

- SCK는 통신하지 않을 때 LOW다.
- 수신 측은 SCK **상승 에지**에서 MOSI를 읽는다.
- 송신 측은 첫 비트를 첫 상승 에지 전에 준비하고, 이후 **하강 에지**에서 다음 비트를 준비한다.
- 8번의 상승 에지로 한 바이트를 받는다.
- 이번 과제는 한 방향씩 확인하므로 **MISO는 연결하지 않는다.** SPI는 양방향 동시 통신도 가능하지만 여기서는 MOSI로만 데이터를 보낸다.
- MCU의 기본 SCK는 약 **781.25 kHz**다. FPGA가 마스터일 때도 **1 MHz 이하**로 만든다.

## 코드 읽기

| 표현 | 뜻 |
|---|---|
| `SPI_HandleTypeDef` | SPI 설정과 상태를 묶은 구조체 자료형 |
| `hspi1` | SPI1을 사용하는 변수 · 헤더에 이미 extern 선언됨 |
| `HAL_StatusTypeDef` | 처리 결과를 나타내는 enum · HAL_OK가 정상 |
| `uint8_t` | 한 바이트 · 0~255 |
| `&tx`, `&rx` | 송신값·수신값을 저장한 공간의 주소 |
| `%02X` | 값을 최소 두 자리 대문자 16진수로 표시 |

`HAL_SPI_Transmit(&hspi1, &tx, 1U, 100U)`는 SPI1로 한 바이트를 보내고 최대 100 ms 기다린다. 통신 클록과 비트 타이밍은 MCU 내부 하드웨어가 만든다. 이번 MCU 예제는 기다리는 방식이며 SPI ISR을 사용하지 않는다.

## MCU 송신 측 · 기본 템플릿 사용

현재 템플릿은 SPI1 마스터다. 다음 코드를 **ece2_474_routine.c의 polling_routine() 대신** 사용한다. 타이머·PWM·UART 인터럽트 시작은 이 실습에 필요하지 않다.

> [!TIP]
> **MCU 송신 예제 · 1초마다 한 바이트 전송**
>
> ```c
> void polling_routine(void)
> {
>     static uint32_t last_ms = 0;
>     uint32_t now_ms = HAL_GetTick();
>     if (now_ms - last_ms < 1000U) return;
>     last_ms = now_ms;
>
>     uint8_t tx = 0x55;
>     HAL_GPIO_WritePin(SPI_CS_ece2_GPIO_Port,
>                       SPI_CS_ece2_Pin, GPIO_PIN_RESET);
>     HAL_StatusTypeDef result =
>         HAL_SPI_Transmit(&hspi1, &tx, 1U, 100U);
>     HAL_GPIO_WritePin(SPI_CS_ece2_GPIO_Port,
>                       SPI_CS_ece2_Pin, GPIO_PIN_SET);
>
>     printf("TX=%02X, result=%d\r\n",
>            (unsigned int)tx, (int)result);
> }
> ```

result가 0인 것은 MCU 송신 함수가 정상 종료했다는 뜻이다. 상대가 데이터를 정확히 받았는지는 **수신 측 출력으로 별도 확인**한다. 보내는 값을 0x55, 0xA5, 0x00, 0xFF로 바꿔 비교한다.

## MCU 수신 측 · SPI1 슬레이브로 변경

수신 MCU도 기본 템플릿에서 시작한다. **송신 측은 기본 마스터 설정을 유지**하고, 아래 코드는 **수신 측에만 적용**한다. main.c나 CubeMX를 수정하지 않고 ece2_474_init()에서 SPI1을 슬레이브로 다시 설정한다.

수신 측의 장치 선택 입력은 **PA4 · SPI1 NSS**다. 송신 측 PB6와 같은 핀 번호로 연결하는 것이 아니다.

> [!TIP]
> **ece2_474_routine.c의 include 아래, 함수 밖에 추가**
>
> ```c
> #define SPI_NSS_RX_ece2_Pin       GPIO_PIN_4
> #define SPI_NSS_RX_ece2_GPIO_Port GPIOA
> ```
>
> **수신 측 ece2_474_init() 교체**
>
> ```c
> void ece2_474_init(void)
> {
>     if (HAL_SPI_DeInit(&hspi1) != HAL_OK)
>         Error_Handler();
>
>     hspi1.Init.Mode = SPI_MODE_SLAVE;
>     hspi1.Init.NSS = SPI_NSS_HARD_INPUT;
>     if (HAL_SPI_Init(&hspi1) != HAL_OK)
>         Error_Handler();
>
>     GPIO_InitTypeDef gpio = {0};
>     gpio.Pin = SPI_NSS_RX_ece2_Pin;
>     gpio.Mode = GPIO_MODE_AF_PP;
>     gpio.Pull = GPIO_PULLUP;
>     gpio.Speed = GPIO_SPEED_FREQ_LOW;
>     gpio.Alternate = GPIO_AF5_SPI1;
>     HAL_GPIO_Init(SPI_NSS_RX_ece2_GPIO_Port, &gpio);
> }
> ```
>
> **수신 측 polling_routine() 교체**
>
> ```c
> void polling_routine(void)
> {
>     uint8_t rx = 0;
>     HAL_StatusTypeDef result =
>         HAL_SPI_Receive(&hspi1, &rx, 1U, 2000U);
>     if (result == HAL_OK)
>     {
>         printf("RX=%02X\r\n", (unsigned int)rx);
>     }
>     else if (result == HAL_TIMEOUT)
>     {
>         printf("RX timeout: check sender, SCK, MOSI, CS and GND\r\n");
>     }
>     else
>     {
>         printf("RX error=%d\r\n", (int)result);
>     }
> }
> ```

PA4는 기본 템플릿에서 다른 기능에 사용하지 않는 핀이며, 위 초기화에서만 NSS 입력으로 설정한다. GPIO_InitTypeDef는 GPIO 설정을 묶은 구조체다. gpio.Pin처럼 점 뒤의 이름으로 각 항목을 설정한다.

수신 측을 먼저 실행해 입력을 기다리게 하고 송신 측을 실행한다. 2초 동안 수신하지 못하면 RX timeout 메시지가 나오므로 송신 측 실행 상태와 배선을 확인한다. 송신 측을 실행하지 않았을 때의 타임아웃은 정상적인 대기 결과다. 수신 결과는 기존 **9600 VCP UART**와 Serial Monitor로 확인한다. 이 예제는 1초마다 보내는 한 바이트를 확인하는 용도다.

## 연결과 역할 교대

| 신호 | MCU 마스터 · 송신 | MCU 슬레이브 · 수신 |
|---|---|---|
| SCK | PB3 · SPI_SCK_ece2 | PB3 · SPI_SCK_ece2 |
| MOSI | PA7 · SPI_MOSI_ece2 | PA7 · SPI_MOSI_ece2 |
| CS / NSS | PB6 · SPI_CS_ece2 | PA4 · SPI_NSS_RX_ece2 |
| GND | GND | GND |

**MCU–MCU(과제9)와 FPGA–FPGA(과제12)만 A–B, C–D, E–F, G–H, I–J끼리 연결한다. MCU–FPGA(과제10·11)는 자기 조의 MCU와 FPGA로 진행하며, 옆 조와 함께할 필요가 없다.** 앞 조가 마스터·뒤 조가 슬레이브로 먼저 실행한 뒤 역할을 교대한다. 역할 교대 때는 프로그램뿐 아니라 **CS 연결도 새 마스터의 PB6 → 새 슬레이브의 PA4**로 바꾼다.

FPGA 연결도 SCK·MOSI·CS·GND를 사용한다. **MCU에는 XDC가 없고**, MCU 핀은 위 연결표와 제공된 C 초기화 코드로 정해진다. **FPGA 쪽 핀만 FPGA 프로젝트의 XDC에서 지정**하고 실제 FPGA 보드 커넥터와 맞춘다. MCU가 수신이면 FPGA의 CS를 MCU **PA4**로 연결한다. GND를 공통으로 연결하고 신호는 3.3 V 기준으로 사용한다.

## 오실로스코프 확인

SCK, MOSI, CS를 관찰하고 프로브의 GND는 공통 GND에 연결한다. 장비 채널 수가 부족하면 SCK와 MOSI부터 보고 CS를 따로 확인한다.

1. CS가 LOW인 구간에 통신이 이루어지는지 확인한다.
2. SCK가 LOW 대기 상태인지, 한 바이트에 상승 에지가 8번인지 확인한다.
3. MOSI를 상승 에지에서 읽으면 0x55는 **0 1 0 1 0 1 0 1**, 0xA5는 **1 0 1 0 0 1 0 1**인지 확인한다.
4. SCK 주기를 측정해 주파수를 구한다.

## 직접 작성할 과제 · 총 5개

아래 순서로 모두 수행한다. FPGA의 송신·수신 Verilog는 직접 작성한다.

### STM32_3_과제8 · MCU 송신 파형 확인

MCU 송신 예제를 실행하고 오실로스코프로 SCK·MOSI·CS를 확인한다. 송신값을 바꾸며 실제 비트 순서와 클록 주파수를 기록한다.

### STM32_3_과제9 · MCU → MCU 수신 확인

지정된 조끼리 MCU 보드 두 대를 연결한다. 수신 측의 **VCP UART**에 출력되는 값이 송신값과 같은지 확인한다. 마스터·슬레이브 역할을 교대해 각자 송신과 수신을 모두 실행한다.

### STM32_3_과제10 · MCU → FPGA 수신 구현

**자기 조의 MCU와 FPGA를 사용한다. 다른 조와 연결하지 않는다.**

FPGA에서 CS 확인, SCK 상승 에지 검출, 8비트 수신과 수신 완료 처리를 구현한다. 받은 값을 **FPGA UART**로 PC에 출력해 MCU의 송신값과 비교한다. 입력 동기화와 시프트 레지스터·비트 카운터를 사용하고, 먼저 TB에서 비트 순서와 CS 해제 후 다음 바이트 수신을 확인한다.

### STM32_3_과제11 · FPGA → MCU 송신 구현

**자기 조의 FPGA와 MCU를 사용한다. 다른 조와 연결하지 않는다.**

FPGA를 마스터로 만들고 **1 MHz 이하의 SCK**, CS, MOSI를 출력한다. 1초마다 한 바이트를 보낸다. 첫 상승 에지 전에 최상위 비트를 준비하고 하강 에지에서 다음 비트로 바꾼다.

오실로스코프로 파형을 먼저 확인한 뒤, 슬레이브로 설정한 MCU에 연결한다. 수신 MCU의 **VCP UART** 출력이 FPGA 송신값과 같은지 확인한다.

### STM32_3_과제12 · FPGA → FPGA 송수신 확인

지정된 조끼리 FPGA 두 대를 연결한다. 한쪽은 과제11의 마스터 송신 회로, 다른 쪽은 과제10의 슬레이브 수신 회로를 사용한다. 받은 값을 **수신 FPGA의 UART**로 출력해 확인하고 역할을 교대한다.

## 이번 주차의 실습 범위

이번 주차는 SPI 과제8~12에 집중한다. 교재의 FPGA ADC 실습은 STM32_1, DAC 실습은 STM32_2에서 진행한다.
